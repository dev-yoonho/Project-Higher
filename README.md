## 프로젝트를 하는 이유

재미를 느끼면서 끝까지 완성하고, 취업에도 보여줄 수 있는 로봇 프로젝트를 만든다. 새로운 장비나 기술을 계속 추가하기보다, 정한 범위 안에서 작동하고 다시 재현할 수 있는 결과를 남기는 것이 우선이다.

관심의 중심은 현실에서 움직이는 로봇이다. 우선 시뮬레이션에서 심층강화학습으로 보행 같은 운동 능력을 학습하고, 조건을 바꾸어 성능을 확인한다. 여기서 쌓은 이해와 검증 결과를 바탕으로 장기적으로 실물에 접근한다.

## 중점 가치

1. **작더라도 완성한다.** 거대한 최종 로봇을 한 번에 만들려 하지 않는다. 현재 완료 기준을 충족하는 결과부터 만든다.
2. **만드는 과정도 재미있어야 한다.** 취업에 도움이 된다는 이유만으로 흥미가 없는 소프트웨어 프로젝트로 바꾸지 않는다. 로봇의 동작을 학습시키고 이해하는 과정이 중요하다.
3. **학습·실험·평가를 직접 경험한다.** 남의 데모를 실행하는 데서 끝내지 않는다. 내 PC에서 정책을 학습하고 저장·재실행하며, 무엇이 달라졌는지 설명할 수 있어야 한다.
4. **전체 과정에서 헤매는 시간을 줄인다.** 설치의 간편함뿐 아니라 튜토리얼, 예제, 문서, 이후 확장 경로까지 함께 고려한다.
5. **결과를 근거로 판단한다.** 보기 좋은 영상과 함께 수치, 실행 조건, 실패와 개선 과정을 남긴다. 다른 사람의 성공 사례를 내 환경에서 검증된 사실로 취급하지 않는다.
6. **시뮬레이션의 범위를 이해한다.** 현실과 완전히 동일한 가상 세계를 만드는 것이 첫 목표는 아니다. 보행이 된다고 전원·회로·발열·부품 선정까지 검증되는 것은 아니다.

RTX 5070에서 버전별 성능을 비교해 2.3.2가 가장 빠르다고 판단한 것은 아니다. 상세 선택 이유는 복습 노트 5번에 기록했다.

현재 환경에서 PyTorch의 GPU 행렬 곱셈과 Isaac Sim 단독 창 실행을 확인했다. 이후 Isaac Lab에서 Cartpole 4개 환경을 `cuda:0`으로 실행해 headless 32스텝, GUI 120스텝의 관측·보상 및 정상 종료를 확인했다. 이후 Ant 32환경 학습과 4환경 평가를 수행했다. 목표 속도 추종과 대규모 병렬 실행은 아직 미검증이다. `cu128`은 설치한 PyTorch 빌드의 구분이며 시스템 CUDA Toolkit과 드라이버는 변경하지 않았다.

C 드라이브 여유는 Miniconda 환경 준비 후 측정 당시 약 269.2GiB였다. 이후 설치·캐시·학습 기록에 따라 추가 공간을 사용한다.

다음 관절 실습은 공식 Cartpole 모델 하나를 사용한다. 수레의 직선 관절 목표를 가상 시간 3초마다 `0 → +0.5 → -0.5 → 0m`로 바꾸고, 목표·실제 관절 위치·오차를 비교한다. 수레에는 위치 제어 구동 모델을 설정하고 막대에는 구동 토크를 주지 않는다. 막대가 넘어지거나 흔들리는 것은 예상되는 관찰이며, 균형 제어나 강화학습은 이번 범위가 아니다. 필요한 설명은 코드 주석과 복습 노트의 관절 항목에 간결하게 기록했다.

기존 관절 실습 완성본은 로컬 v2.3.2 API와 Python 구문을 확인해 준비했으며 실제 실행 결과는 아직 미확인이다. 해당 전체 코드를 채팅으로 제공하여 사용자가 직접 입력한다. `02_joint_practice.py`는 사용자가 생성할 파일이며 아직 생성·실행을 확인하지 않았다. 실행 후 3~4.5초의 출력에서 목표와 실제 위치를 비교한다.
